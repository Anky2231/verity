1. What Verity does

Verity checks marketing content against a brand's guidelines and explains every flag with the clause it breaks, a confidence score and a suggested fix. People make the final call: a Creator, Manager, Approver workflow with a tamper-evident audit trail. Nothing is published automatically.

Manager
uploads guidelines, reviews extraction, publishes a version
→
Creator
writes content, runs the agents, fixes or disputes flags
→
Manager
approves, rejects or escalates
→
Approver
final sign-off
→
Audit trail
every step recorded

2. Finished and working on the live link

AreaWhat works
Guideline builderUpload PDF, DOCX, TXT or MD (or use the sample). Extracts rules, approved terms, approved claims with source pages and a voice profile. Editable preview with notes on anything unclear. Publishing creates a new immutable version.
Review editorHighlight on every flagged span, severity by colour and underline style, flags follow the text as it is edited.
AgentsTermGuard (banned and approved terms, singular, plural and hyphen variants, allowed contexts). ClaimGuard (unsupported claims matched to the approved claims register with document and page, wrong numbers flagged). ToneGuard (labelled basic mode, see section 5). MetaAgent merges overlaps, ranks flags and computes a 0 to 100 score.
Findings panelClause citation, quoted text, confidence bar, plain-English reason, suggested fix. Accept fix, edit, dispute (a written reason is required).
ReliabilityResults stream as each agent finishes. One failing agent never blocks the others. Result cache, rate limiting, labelled fallback result for the sample text if the AI service is down.
WorkflowSubmit, approve, reject with reason, escalate, final approval, send back, publish. Roles enforced on the server. Nobody can approve their own content. Queue with score, open flags, change since last revision and age. Comments and in-app notifications.
Revisions and auditEvery run is an immutable revision with a word-level diff and compliance change. Audit log is append-only and hash-chained; "Verify chain" recomputes it; filter and export as CSV or JSON.
DashboardReviews, average score, time to approve, AI versus human flags, score trend, violations by agent, content type and creator, clauses reviewers keep overriding.
Learning loopA rule that reviewers dispute or override in at least half of 5 or more decisions gets a higher confidence cutoff; borderline flags become suggestions and stop lowering the score.
EngineeringOpenAPI 3.1 reference for all 25 routes (checked against the code by a test), pagination, request ids and logging, security headers, input validation, optional BullMQ and Redis queue, server-waking message.
AccessibilityAutomated audit with no serious or critical violations in light and dark mode, keyboard-only journey, no horizontal scroll at 320 px or 200% zoom.

3. Architecture and technology

ServiceTechnology and role
Web (Vercel)Next.js 14, React 18, TipTap/ProseMirror. Interface only; every permission is re-checked by the API.
API (Render, free)Node.js and Express. JWT demo logins, role checks, workflow state machine, SSE streaming, cache, rate limiter, audit log, analytics, guideline versioning.
AI servicePython FastAPI and Pydantic. Runs the agents in parallel and merges them. Same container as the API on Render.
Database (Neon, free)PostgreSQL with JSONB. brand_id on every table. Locally and in tests an in-process Postgres (PGlite).
Queue (optional)BullMQ and Redis run one job per agent when REDIS_URL is set; otherwise a direct pipeline runs. Not enabled on the live demo.

Technically hard parts

  • Span integrity. Models are poor at character offsets. Agents return the quoted text; the server computes and verifies the offsets, re-locates or drops mismatches; a mapping layer converts text offsets to editor positions. Tested with Unicode, repeated phrases and newlines.
  • Tamper-evident audit log. One SQL statement computes each hash from the previous row; a unique constraint stops forks under concurrency; triggers reject update, delete and truncate.
  • Calibration from reviewer overrides, per rule, with the effect visible on the dashboard.
  • Graceful degradation. Per-agent isolation, a circuit breaker around the optional queue, honest labels on every fallback.

5. What does NOT work yet

  • ToneGuard on the live demo is rule-based basic mode, not the LLM: it catches jargon, hype, shouting and pressure wording, not subtle voice problems. LLM latency has not been measured.
  • Free hosting sleeps when idle; the first visit can take 30 to 60 seconds (the page says so).
  • Demo data is shared: every visitor sees the same reviews and each other's changes.
  • Known detection errors: ClaimGuard flags "only" in "Limited time only" and "best" in "best-in-class"; TermGuard flags "Java" meaning the language and "Joe's Diner" unless the brand lists them as allowed contexts. The test sets are small.
  • Guideline extraction is rule-based and can miss unusual layouts; scanned (image-only) PDFs are not read.
  • Email notifications are built but off; in-app notifications work.
  • Cache and rate limiter are per server process. Sign-in is demo logins only.
  • Dashboard summary queries read every review (about 50 to 90 ms at 20,000 reviews); not optimised further.
  • No usability test with outside people and no screen-reader testing yet; automated accessibility checks and a keyboard-only run were done.
  • Round 3 items not built: VisualGuard, multi-brand workspaces, Brand Drift Intelligence, tone embeddings.

6. Three improvements for Round 3

ImprovementWhat it changes for the user, and how it will be tested
1. VisualGuard
image and logo compliance		A creator uploads a banner and gets the same kind of flag on the image, with the clause, before a manager sees it. Image embeddings against approved assets, palette check, logo clear-space and misuse checks, using the existing finding format with an image region. Test: at least 85% recall on a 30-image set, at most 10% false flags on compliant images. In place: brand_assets table, guarded upload route, region field.
2. Multi-brand workspaces
agency mode		A manager switches between client brands, each with its own guidelines, reviews and analytics, and shares a read-only compliance report. Per-brand membership, isolation, a cross-brand contamination detector. Test: automated tests prove no cross-brand reads or writes; at least 80% of planted cross-brand samples flagged. In place: brand_id on every table, scoped queries, a second brand in the seed.
3. Brand Drift IntelligenceA brand manager sees which teams and clauses drift over time and is alerted before violations pile up. Rolling-window tone analysis against the brand centroid, per-team drift score, weekly digest. Test: on a seeded history with planted drift, the alert fires within one window and not on a stable control series. In place: stored revision history, 40 seeded reviews, override-rate analysis.
