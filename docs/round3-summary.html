1. What Verity does, and what Round 3 added

Verity checks marketing content against a brand's guidelines and explains every flag with the clause it breaks, a confidence score and a suggested fix. People make the final call: Creator, Manager and Approver roles with a tamper-evident audit trail. Nothing is published automatically. Round 2 delivered the text workflow (guideline builder, TermGuard, ClaimGuard, ToneGuard in basic mode, MetaAgent scoring, approval workflow, audit trail, dashboard). Round 3 adds the three improvements promised, and closes several Round 2 gaps.

4. Architecture and technology

ServiceTechnology and role
Web (Vercel)Next.js 14, React 18, TipTap. Interface only; every permission is re-checked by the API.
API (Render, free)Node.js and Express. JWT demo logins; a brand-context middleware that sets the active brand and the user's role in it; workflow state machine; SSE; cache and rate limiter; audit log; drift analysis; client reports.
AI servicePython FastAPI, Pydantic, Pillow, NumPy, OpenCV (headless). Text agents, MetaAgent, VisualGuard. Stateless: guidelines, logos and palette are sent with each request. Same container as the API.
Database (Neon, free)PostgreSQL with JSONB; memberships, assets and images (bytea), share links, drift digests; brand_id on every table.

Hard parts

  • Logo checks without a model. Template matching on edge maps: a coarse search over 22 sizes and 11 stretches, then a precise match; a stretched fit must score clearly higher than the undistorted logo to count as distortion; a second pass on colour edges finds a recoloured logo; recolouring is judged per logo colour.
  • Provable brand isolation. One middleware decides the brand and role; a test calls every review route from the other brand; breaking the filter on purpose makes that test fail.
  • A drift detector that stays quiet. A Poisson standard error widened by a measured dispersion factor, a minimum rise of 1.3 times, and a threshold chosen on one simulated set and measured on another.
  • Honest degradation. Per-agent isolation, labelled fallbacks, a circuit breaker around the optional queue, memory kept under the free host's limit (about 210 MB peak for a large image).

5. Testing notes

  • Automated: 102 API tests run by default (4 more need Redis or the real AI service, and run in CI), 127 AI tests, 7 web unit tests, lint, build, and browser suites in real Chrome: full journey, accessibility audit (0 serious or critical violations), keyboard-only runs, 320 px reflow, sleeping server, multi-brand, drift, image reviews against the real AI service, queue, Round 3 keyboard use. All run in GitHub Actions on every push.
  • Evaluation sets: text agents (30 + 30 texts), contamination (39 texts), images (30 dev + 30 held-out + 20 stress), drift (simulated teams). Thresholds were set on dev data. Held-out and stress sets were not used to tune, except that the two ClaimGuard patterns fixed in Round 3 were already-known held-out errors.
  • Found by the new tests while building: stale rows after switching brand; weeks starting on Thursday; images returned as JSON; a text charset added to image types; the 2 MB request limit; plain banners matched as a retired logo.

6. What changed from the plan, and why

  • VisualGuard uses classical image processing, not CLIP: CLIP needs more memory than the free 512 MB host and a model download. It costs nothing and takes 1 to 2 seconds per image.
  • Drift uses violation rates, not tone embeddings (no embedding model on the free host; the embedding experiment in Round 2 did not help).
  • No S3: logos and reviewed images live in PostgreSQL. The weekly digest is created on first view of a new week because the free host has no scheduler. Teams are a field on a brand membership.

7. What does NOT work yet

  • ToneGuard on the demo is rule-based basic mode, so subtle voice problems are not caught.
  • VisualGuard misses rotated and cropped logos and treats photographs as off-palette; it knows the brand's logo files, not "off-brand" in general. Test images are synthetic, so real designs will score lower.
  • Other-brand detection does not catch wording with no listed term, claim or name.
  • Drift needs about 7 weeks of history per team; mild drifts are often missed; the history is simulated and seeded.
  • No usability test with outside people and no screen-reader test. The demo data is shared by every visitor. The free host sleeps when idle. Email is built but off.
